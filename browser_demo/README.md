# BelVoice у браўзары — працоўны прататып

**Гатовае дэма: [belvoice.gomzik.xyz](https://belvoice.gomzik.xyz).**
Поўная паслядоўнасць ад чыстага clone да запуску такой жа старонкі —
у [галоўным README](../README.md#як-атрымаць-такое-ж-дэма-з-зыходнікаў).

**Пакрокавая інструкцыя: [як сабраць арыгінальны і жаночы галасы](VOICES.md).**

## Выкарыстанне як бібліятэкі

Чысты ESM API без UI: [`belvoice.js`](belvoice.js), дакументацыя —
[`LIBRARY.md`](LIBRARY.md). Дэма ніжэй выкарыстоўвае той самы API.
Каманда `uv run python tools/browser_demo/package_library.py` з кораня
рэпазіторыя стварае гатовую да капіявання папку `dist/belvoice/` без HTML,
з усімі мадэлямі/WASM і Gleam FFI bindings.

## Запуск гатовай папкі

Пасля чыстага clone спачатку выканайце [перазборку](#перазборка-з-рэпазіторыя):
нейрасеткі, слоўнікі і WASM не захоўваюцца ў Git.

```bash
cd browser_demo
python serve.py
```

Адкрыць **http://localhost:8000**, увесці беларускі тэкст і націснуць
**«Агучыць»**. Вынік прайграваецца; можна таксама праслухаць яго праз плеер
і спампаваць як WAV (PCM16, mono, 22050 Hz).

`serve.py` — звычайны статычны сервер без залежнасцяў, але з COOP/COEP-загалоўкамі
для шматпаточнага WASM. Ён запускаецца на лакальным адрасе; Ctrl+C — спыніць.
Можна запускаць і з кораня рэпазіторыя: `python browser_demo/serve.py`.
Іншы порт: `python serve.py --port 8001`. Папка па змаўчанні вылічаецца адносна
скрыпта, а не бягучага каталога.

У дыягностыцы павінна быць `crossOriginIsolated=true`, а фактычная колькасць
патокаў паказваецца пасля загрузкі мадэляў. Калі старонка была адкрытая раней,
абнавіце яе. Для шматпаточнасці адкрывайце праз `localhost`/`127.0.0.1` ці HTTPS;
звычайны HTTP на LAN-адрасе не гарантуе secure context.

Ранейшы `python -m http.server` таксама працуе, але без шматпаточнасці.
Скрыпт прызначаны для лакальнага дэма, не для прадакшн-хостынгу.

Патрэбны сучасны Chromium/Chrome/Firefox з WASM SIMD, ES modules, Worker і
DecompressionStream. Рэальна праверана ў Chromium 156 на Linux; іншыя браўзары
і OBS пакуль не правераныя. `file://` не падыходзіць — выкарыстоўвайце HTTP.
Гатовая папка можа быць скапіявана на іншы камп’ютар цалкам. Для яе працы
не патрэбныя `.venv`, Java, PyTorch, Node.js, Maven або інтэрнэт. Python у камандзе
вышэй толькі раздае статычныя файлы, а не апрацоўвае тэкст ці аўдыё.

Пры першым націсканні загружаюцца **лакальныя** мадэлі і слоўнік. У старонцы
бачныя прагрэс загрузкі, падрыхтаваны тэкст, фанемы, час кожнага этапу і памылкі.
Адна старонка трымае адзін Worker, тры галасавыя ONNX-сесіі і адну GrammarDB у памяці
(плюс лянівую сесію StressML, калі яна патрэбная).
Наступны запыт выкарыстоўвае іх паўторна. Паралельныя запыты не падтрымліваюцца.
Перазагрузка старонкі знішчае гэтыя сесіі.

## Дэма на Netlify і вымярэнне часу

### Выбар голасу

Рэгулятар **«Хуткасць маўлення»** задае тэмп ад 0.5× да 2× (па змаўчанні
1×); для жаночага голасу можна пачаць з 1.25–1.4×. Гэта кіраванне
працягласцямі ў GlowTTS (`length_scale / speed`), а не паскарэнне аўдыяплэера:
новы WAV таксама будзе карацейшы/даўжэйшы без зруху тону праз рэсэмплінг.
Дакладнае стаўленне працягласцяў прыблізнае праз акругленне кадраў і мінімальныя
працягласці токенаў. Якасць на крайніх хуткасцях можа пагаршацца. Змена тэмпу
не патрабуе перазагрузкі мадэляў; значэнне захоўваецца пры выбары іншага голасу.
Актуальная поўная зборка з рэгулятарам: **`dist/belvoice-demo/`**.

У дэма даступныя **арыгінальны alex73** і **жаночы slapula №1**
([model card](https://huggingface.co/slapula/commonvoice_be_tts_female_1), MIT).
Абодва выкарыстоўваюць GlowTTS + HiFi-GAN і той жа BelG2P/StressML frontend.
Загрузка мадэляў пачынаецца толькі пасля «Агучыць», для выбранага голасу.

Экспартаваць жаночы голас без змены арыгінальных чэкпойнтаў:

```bash
uv run --extra browser-demo python tools/browser_demo/export_models.py --voice female-1
```

Зафіксаваная HF-рэвізія: `95b899d31a13278364b85b88f953e92df2ff4826`.
У гэтай мадэлі нармалізацыя па сярэднім/стандартным адхіленні з
`scale_stats_female_1.npy`, а не абмежаванне mel да [-4, 4]. Экспарт улічвае
гэта і правярае вынік адносна Python на трох фразах рознай даўжыні.
Дадатковыя ONNX-файлы займаюць каля 163 MiB.

Пры пераключэнні стары Worker спыняецца разам з яго сесіямі, каб не трымаць
два рухавікі адначасова. Новы голас ініцыялізуецца нанова; frontend і StressML
таксама пераствараюцца, але ўжо атрыманыя файлы могуць выкарыстоўваць HTTP-кэш.
Паўторныя сінтэзы без змены голасу выкарыстоўваюць тыя ж сесіі. Пераключальнік
недаступны падчас загрузкі/сінтэзу. Таймер пачатковай загрузкі скідаецца для
кожнага новага рухавіка.

Новая поўная зборка з двума галасамі:

```bash
uv run python tools/browser_demo/package_library.py --demo --refresh
uv run --extra browser-demo python tools/browser_demo/test_voice_browser.py --demo dist/belvoice-demo
```

Для Netlify выбірайце **`dist/belvoice-demo/`** цалкам (~376 MiB).
Для інтэграцыі ў іншы праект — **`dist/belvoice/`**, без інтэрфейсу.
Папкі абнаўляюцца на месцы, новыя імёны зборак не патрэбныя.
Памер загрузкі аднаго выбранага голасу не падвойваецца: іншы набор мадэляў
не запытваецца, пакуль яго не выберуць.

`dist/belvoice/` — бібліятэка без HTML, не гатовая дэма-старонка.
Падрыхтаваць асобны статычны каталог з дэма:

```bash
uv run python tools/browser_demo/package_library.py --demo --refresh
```

Заліць **увесь каталог `dist/belvoice-demo/`** праз Netlify Deploy manually /
Netlify Drop. `index.html` і `_headers` павінны быць у корані загружанага
каталога. Build command і Python на хостынгу не патрэбныя. `--refresh` абнаўляе
ранейшую зборку толькі пасля праверкі manifest/SHA-256: пры дадатковых або
змененых файлах ён адмовіцца перазапісваць каталог.

`_headers` задае COOP `same-origin` і COEP `require-corp` для WASM-патокаў.
Пасля запуску праверце ўнізе старонкі `crossOriginIsolated=true` і колькасць
патокаў (аўтаматычна да 4, залежыць ад браўзара і працэсара). Без ізаляцыі
выкарыстоўваецца адзін паток, што можа істотна запаволіць сінтэз.

На старонцы асобна паказваюцца:

- першая загрузка і падрыхтоўка (разам са стартам Worker), у тым ліку час
  ініцыялізацыі ONNX/WASM; гэта не толькі спампоўванне;
- час сінтэзу і яго этапаў: тэкст/ML, энкодэр, дэкодэр, вакодэр;
- агульнае чаканне ад націскання кнопкі да гатовага аўдыя, да пачатку прайгравання.

Асобныя файлы і час іх атрымання бачныя ў дыягностыцы. Лянівая загрузка
StressML не ўваходзіць у пачатковую загрузку; яна ўваходзіць у ML-этап сінтэзу.
Для параўнання трэба агучыць аднолькавы тэкст двойчы з аднолькавым ML-рэжымам:
першы запыт загружае і ініцыялізуе рухавік, другі выкарыстоўвае мадэлі ў памяці.
Пасля перазагрузкі старонкі ініцыялізацыя паўтараецца, а файлы могуць прыйсці
з браўзернага кэша. Агульны аб'ём статычных файлаў з двума галасамі каля 376 MiB; улічвайце
трафік і абмежаванні тарыфу хостынгу. Сам сінтэз ідзе на камп'ютары наведвальніка.

## Пераключальнік StressML

У дэма ёсць **«Выкарыстоўваць StressML для невядомых слоў»** (па змаўчанні
выключаны). Можна агучыць адзін тэкст з ім і без яго, не перазагружаючы старонку.
Напрыклад: `Прывітанне, стрымерскі рудзі! Му́ка.`

Пры ўключэнні ML дапрацоўвае толькі шматскладовыя невядомыя словы. Ручныя
націскі і `StressStat` маюць прыярытэт; словы з GrammarDB/слоўніка фанетыкі
прапускаюцца. Для «о/ё» захоўваецца існуючая эўрыстыка BelG2P. Гэта не
кантэкстнае вырашэнне амографаў і не гарантыя правільнага націску ў імёнах.

На старонцы паказваюцца змененыя словы, прадказаныя націскі, ацэнка ўпэўненасці
і час ML. Упэўненасць — выхад мадэлі, не вымераная гарантыя дакладнасці.
Дадатковая мадэль **~18,3 MiB** загружаецца толькі калі ML уключаны і ёсць
слова, якому яна патрэбная; далей сесія і абмежаваны кэш прадказанняў захоўваюцца.
Выключэнне пераключальніка спыняе выкарыстанне ML, але не выкідае ўжо загружаную
мадэль з памяці. `dispose()`/перазагрузка старонкі вызваляе ўсё.

Калі ўвесь тэкст вядомы GrammarDB, вынік з ML можа супасці з вынікам без ML.
Націскі, дададзеныя GrammarDB ўнутры фанемізатара, не ўсе бачныя ў полі тэксту;
у фанемах яны прысутнічаюць незалежна ад пераключальніка.

  stress-ml-config.json, stress-ml-verification.json
  config.json                — сапраўдныя ID токенаў і параметры checkpoint-а
  verification.json          — параўнанне экспарту з PyTorch
  female-1/                  — асобны encoder/decoder/vocoder і канфіг жаночага голасу

  belg2p.mjs                 — фанетычныя правілы BelG2P 1.0.0, скампіляваныя TeaVM

  resources.json             — арыгінальныя табліцы правілаў і рэсурсы
  adapted-source.tar.gz      — дакладны адаптаваны Java-код для перазборкі

Агульны памер аднаго голасу з StressML — каля **213 MiB**, з двума — **376 MiB**. Распакаваная
GrammarDB займае больш памяці, чым gzip-файл: толькі JSON-тэкст — каля 133 MiB,
плюс аб’екты і мадэлі. Гэта яшчэ не аптымізаваны па памяці прадукт.

### Сінтэз

1. JavaScript выконвае тую ж `NormalizationSimple` і `StressStat`, што CLI.
   Спачатку вербалізуюцца цэлыя лікі без кантэксту: `1000` → «адна тысяча»,
   `2026` → «дзве тысячы дваццаць шэсць», `-42` → «мінус сорак два».
   Падтрыманыя лікі да 18 лічбаў і разрадныя прабелы (`1 000`, NBSP, вузкі NBSP).
   Пачатковыя нулі і паслядоўнасці даўжэйшыя за 18 лічбаў чытаюцца па лічбах;
   перапоўнення ці акруглення праз JavaScript Number няма. Няма скланення
   паводле суседніх слоў або распазнавання дат, валют, тэлефонаў і дробаў.
   Пасля гэтага выконваецца **ўвесь** `NormalizationSimple.C2NAME` адным
   пасімвальным праходам, уключаючы прабелы ў заменах і невядомыя сімвалы.
   Падтрыманыя спецыяльныя знакі: `@→слімак`, `%→працэнт`, `+→плюс`, `=→роўна`,
   `€→еўра`, `$→долар`, `#→рашотка`, `&→амперсанд`, `<→менш`, `>→больш`.
   Напрыклад, `<3` чытаецца як «менш тры». Гэта фіксаваныя назвы без
   кантэкстнага скланення; звычайная пунктуацыя не замяняецца словамі.
   `NormalizationLLM` — асобны модуль
   са знешняй моўнай мадэллю, а не частка `NormalizationSimple` ці гэтага дэма.
2. BelG2P працуе як JavaScript, **без JVM**. Арыгінальныя фанетычныя працэсы,
   выбар націскаў і серыялізацыя захаваныя. Адаптаваныя толькі сховішча GrammarDB,
   чытанне рэсурсаў і статычная дыспетчарызацыя замест Java reflection.
   JAXB-структуры замяняюцца простымі DTO з тымі ж патрэбнымі палямі.
   Для TeaVM таксама зменены тып абгорткі памылак, парадак толькі адладачнага
   спіса і UTF-8 key=value reader для табліц гукаў.
3. Фанемы пераводзяцца ў гістарычную натацыю GlowTTS і сапраўдныя ID токенаў,
   уключаючы blank/BOS/EOS. Гэта не транслітарацыя і не звычайны IPA.
4. Энкодэр GlowTTS выдае сярэднія значэнні і працягласці. Пашырэнне па
   працягласцях выконваецца ў JS, flow-дэкодэр — у ONNX/WASM.
5. HiFi-GAN выдае PCM, які прайграваецца праз Web Audio.

Абодва галасы маюць `inference_noise_scale=0`, таму выпадковы шум не патрэбны.
У арыгінальнага голасу audio configs без статыстык нармалізацыі: пераход
GlowTTS → HiFi-GAN эквівалентны clip да [-4,4]. У жаночага голасу аднолькавыя
mean/variance-статыстыкі ў абедзвюх сетак узаемна скасоўваюцца, таму clip не
ўжываецца. Вагі і checkpoint-ы не перанавучаліся; экспартаваны толькі інферэнс.
Па змаўчанні WASM выбірае колькасць патокаў аўтаматычна (да 4); без isolation
выкарыстоўвае 1. Таму звычайны `http.server` працуе без спецыяльных загалоўкаў.
Незалежна ад колькасці патокаў дапускаецца адзін сінтэз за раз на экзэмпляр.

## Праверкі і хуткасць

- StressML: экспарт параўнаны з Python на 19 сегментах, у тым ліку даўжэйшых
  за 48 сімвалаў. Рэальны Chromium праверыў рэжымы OFF/ON/OFF/ON, загрузку
  мадэлі толькі адзін раз, захаванне ручных/слоўнікавых націскаў і сапраўдны WAV.
  У тэставым сказе «Прывітанне, стрымерскі рудзі! Му́ка.» ML дапоўніла два словы:
  «стры́мерскі», «рудзі́». Першы ML-этап разам з загрузкай заняў ~91 мс,
  паўторны з кэшам — ~0.6 мс; гэта прыклад замеру, не гарантыя хуткасці ці якасці.

- Экспарт параўнаны з PyTorch на трох даўжынях уваходу; максімальнае адхіленне
  mel каля `3.1e-6`. Дакладныя значэнні ў `models/verification.json`.
- Браўзерны frontend параўнаны з сапраўдным JVM/Python pipeline на **513**
  прыкладах, у тым ліку з табліц BelG2P: **0 разыходжанняў**, 0 прапушчаных.
- Нармалізацыя асобна праверана на ўсіх **76** пасімвальных правілах і
  **3664** уваходах: лікі, разрады, адмоўныя значэнні, пачатковыя нулі,
  вялікія цэлыя, спецыяльныя знакі і `<3`. Поўнае супадзенне Python і JavaScript.
- Рэальны headless Chromium: два тэкставыя запыты, два сапраўдныя WAV,
  актыўны AudioContext, без знешніх запытаў, без cross-origin isolation;
  мадэлі і GrammarDB загружаныя толькі па адным разе.
- Спампаваныя з Chromium WAV параўнаныя з арыгінальнымі PyTorch-мадэлямі:
  RMSE 0.37 і 0.29 адзінкі PCM16, карэляцыя вышэй за 0.99999999.
- Дадаткова правераны тэкст «Подъезд. Съешь ещё этих мягких булок.»:
  набліжаны рэжым выдае папярэджанне, але генеруе сапраўдны WAV; наступны
  беларускі запыт працуе нармальна. Рэшткавыя памылкі і сцяг паміж фразамі не ўтойваюцца.
- На правераным камп’ютары 4.32 с гуку атрымаліся за 8.1–9.2 с вылічэнняў,
  асноўны час — HiFi-GAN; першая загрузка/ініцыялізацыя каля 1.9 с асобна.
  Гэта не гарантыя хуткасці на іншым камп’ютары. Аптымізацыя і WebGPU не рабіліся.

Аўтаматычны тэст правярае сігнал і запуск прайгравання, але не замяняе
суб’ектыўную ацэнку вымаўлення на слых. Браўзерны PCM не ўключае дадатковую
хваставую цішыню, якую дадае Python `Synthesizer.tts`.

## Перазборка з рэпазіторыя

Зборка патрабуе `uv`, Python >=3.12, **JDK 21+ і Maven**; інтэрнэт патрэбны
для загрузкі мадэляў і build-залежнасцяў. JavaScript-тэсты патрабуюць Node.js,
Gleam-тэсты — `gleam` (праверана з 1.19.2). Браўзерныя тэсты выкарыстоўваюць
Chromium: усталяваны сістэмна ці спампаваны праз Playwright.

Вялікія згенераваныя файлы ў `browser_demo/models/`, `g2p/`, `vendor/`, `data/`
выключаныя з Git. Пасля чыстага clone выканаць з кораня BelVoice:

```bash
uv sync --locked --extra browser-demo
uv run --locked --extra browser-demo python tools/browser_demo/export_models.py --voice default
uv run --locked --extra browser-demo python tools/browser_demo/export_models.py --voice female-1
uv run --locked --extra browser-demo python tools/browser_demo/export_stress_ml.py
uv run --locked --extra browser-demo python tools/browser_demo/build_g2p.py
uv run --locked --extra browser-demo python tools/browser_demo/prepare_assets.py
uv run --locked --extra browser-demo python tools/browser_demo/package_library.py --refresh
uv run --locked --extra browser-demo python tools/browser_demo/package_library.py --demo --refresh
uv run --locked --extra browser-demo python browser_demo/serve.py --directory dist/belvoice-demo
```

Пасля гэтага будуць гатовыя абедзве папкі ў `dist/`; пачатковыя `.pth`,
кэшы загрузак і асяроддзе Python наведвальніку старонкі не патрэбныя.
Першая зборка можа спампаваць некалькі GB залежнасцяў і чэкпойнтаў;
памер гатовай поўнай папкі каля 376 MiB, не памер загрузак пры зборцы.
Жаночая мадэль фіксуецца на рэвізіі, пазначанай вышэй; арыгінальная — на
`d7684c1dc4bcfd69708bbc013b251549ae40b1ca`. `uv.lock` захоўвае версіі
Python-пакетаў. Наяўныя арыгінальныя StressML-вагі бяруцца з `framework/`.

Толькі для зборкі BelG2P патрэбныя **JDK 21+ і Maven**. Калі Maven не ў PATH:

```bash
uv run --extra browser-demo python tools/browser_demo/build_g2p.py --maven /path/to/mvn
```

Першая зборка спампоўвае Java-крыніцы BelG2P 1.0.0, зыходнікі reader 1.5.0,
залежнасці TeaVM 0.16.0 і ONNX Runtime Web 1.31.1. Хэшы выкарыстаных архіваў
захоўваюцца побач з артефактамі. Граматычны індэкс экспартуецца з рэальнага
кэшаванага JAR; калі `g2p/grammar.json.gz` ужо ёсць, перазборка выкарыстоўвае яго.

Праверкі:

```bash
uv run python tools/browser_demo/test_normalization.py
uv run --extra browser-demo python tools/browser_demo/test_frontend.py
uv run --extra browser-demo python tools/browser_demo/test_browser.py
uv run python tools/browser_demo/test_demo_server.py
uv run --extra browser-demo python tools/browser_demo/test_browser.py --isolated
node --test tests/browser/*.mjs
uv run python -m unittest discover -s tests/browser -p 'test_*.py'
uv run --extra browser-demo python tools/browser_demo/test_stress_ml_browser.py
uv run --extra browser-demo python tools/browser_demo/test_voice_browser.py --demo dist/belvoice-demo
uv run --extra browser-demo python tools/browser_demo/test_library_browser.py --package dist/belvoice
```

Праверка нармалізацыі патрабуе толькі Node.js і параўноўвае ўсе правілы Python.
Праверка ўсяго frontend патрабуе Node.js і Java. Браўзерныя тэсты самі запускаюць
статычны сервер; `test_browser.py` без `--isolated` правярае аднапатачны fallback,
а voice/ML-тэсты — COOP/COEP. WAV, здымкі старонкі і журналы захоўваюцца ў
`build/browser-tests/` (можна змяніць `--output`). Калі сістэмнага `chromium` няма:

```bash
uv run --extra browser-demo playwright install chromium
```

Тады тэсты скарыстаюцца браўзарам Playwright. Для іншага executable ёсць
`--chromium /path/to/chromium`. Гэта не патрабаванне да наведвальніка дэма.

## Абмежаванні

- Гэта прататып для сучаснага desktop-браўзара; OBS трэба праверыць асобна.
- Націскі амографаў выбіраюцца без аналізу кантэксту; невядомыя словы і імёны
  могуць гучаць няправільна. Ручны націск U+0301 захоўваецца.
- Пры вядомых фанетычных супярэчнасцях BelG2P паўторна апрацоўвае фразу
  з убудаваным `Huk.SKIP_ERRORS=true`, пасля чаго аднаўляе сцяг. Напрыклад,
  немагчымы «мяккі ш» агучваецца цвёрдым `ш`; у дыягностыцы з’яўляецца
  «набліжанае вымаўленне». Новыя літары і фанемы не дадаюцца. Гэта не расейскі
  TTS і не гарантыя апрацоўкі любога пашкоджанага ўводу; іншыя памылкі не хаваюцца.
- `ɐ` набліжаецца да `a`, як і ў лакальным CLI: асобнага токена ў мадэлі няма.
- Цэлыя лікі вербалізуюцца без кантэксту; даты, дробы і адзінкі вымярэння
  асобна не інтэрпрэтуюцца. Лацінка чытаецца назвамі літар.
- Увесь запыт генеруецца перад прайграваннем; струменевага аўдыё няма.
- Няма квантавання, GPU або аптымізацыі памяці. Ёсць статычная ўпакоўка
  бібліятэкі; прадакшн-інтэграцыя і HTTP-загалоўкі застаюцца ў праекце-спажыўцы.
