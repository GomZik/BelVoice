# MOSS-TTS-Nano: незавершаны эксперымент

Асобны WASM/CPU-рухавік з **лакальнымі** ONNX-вагамі: наведвальнік не
звяртаецца да Hugging Face або сервера сінтэзу. Код і вагі пазначаныя Apache-2.0;
гэта не аўтаматычны дазвол на імітацыю любога чалавека. Правы на канкрэтны
аўдыёўзор трэба разглядаць асобна.

**Беларуская не ўваходзіць у 20 заяўленых моў.** Першы браўзерны WAV быў
атрыманы, але карыстальнік паведаміў пра непрымальную якасць. Паспяховая
генерацыя файла не азначае, што мадэль умее гаварыць па-беларуску.
Параўнанне без націскаў і з кантрольным англійскім тэкстам таксама не дало
карыстальніку прымальнай якасці. На англійскім прыкладзе ўсе 39 гукавых кадраў
супалі з арыгінальным Python-рухавіком пры аднолькавых выпадковых ліках;
карэляцыя дэкадаванага mono-гуку — ~0.999999998. Stereo/mono істотнай розніцы
не далі. **Эксперымент прызнаны няўдалым для нашай задачы.** Код захаваны для
магчымых даследаванняў; MOSS не ўключаны ў бягучыя кананічныя `dist/`-пастаўкі
і не прызначаны для інтэграцыі ў Rudzi.

## Падрыхтоўка з зыходнікаў

Пасля звычайнай зборкі browser_demo:

```bash
uv run --locked --extra browser-demo python tools/browser_demo/prepare_moss.py
uv run --locked --extra browser-demo python tools/browser_demo/test_moss_browser.py
```

`--tokenizer-only` у падрыхтоўцы правярае токенізатар без вялікіх вагаў.
Патрэбныя Node.js і існуючы Java toolchain для слоўніка націскаў. Наведвальніку
яны не патрэбныя. Браўзерны runtime — існуючы ONNX Runtime Web 1.31.1.

Падрыхтоўка захоўвае каля 684 MiB inference-рэсурсаў у `browser_demo/moss/`.
Вагі разбітыя на файлы да 8 MiB, каб не загружаць на статычны хостынг адзін
440 MB файл. Энкодэр выкарыстоўваецца толькі падчас зборкі для існуючага
беларускага ўзору BelVoice, не трапляе ў браўзерную пастаўку.
Не варта блытаць памер файлаў з патрэбай у RAM: некалькі ONNX-сесій і
прамежкавыя тэнзары патрабуюць больш памяці. Цяжкія праверкі — па адной.

Рэвізіі і ліцэнзіі захоўваюцца побач з мадэллю:
- TTS: `f52645cb467506d8e18e746ddd59482685b74e58`;
- кодэк: `ceff0d0749bfb3fa2d61149794ec6feef0d1e1ae`;
- Apache-2.0 Python reference: `8b7bcc9341b3b4ef3a3a58ba1338a7d85ff133eb`;
- Hugging Face tokenizers.js 0.2.0, Apache-2.0;
- WSOLA з Apache-2.0 VocoLoco `7fa8601b9864005e473e14b41756d6e963211d97`.

Код асобнага **MOSS-TTS-Nano-Reader не выкарыстоўваецца**: яго README пакуль
пазначае адсутнасць ліцэнзіі на распаўсюд. Наш Worker рэалізуе ONNX-кантракт
ліцэнзаванага асноўнага праекта. Токенізацыя параўноўваецца з SentencePiece;
націскі не выдаляюцца падчас нармалізацыі.

## Лакальны API і абмежаванні

```js
const voice = createBelVoice({voice: 'moss'});
const audio = await voice.synthesize('Прывітанне!', {
  useStressML: true,
  speed: 1,
  mossMaxFrames: 375,
});
voice.dispose();
```

- Нармалізацыя лікаў і сімвалаў — наша.
- `useStressML` захоўвае поўны лакальны ланцужок:
  ручныя націскі → адзіная о/ё → адназначны GrammarDB → StressStat → StressML.
  Можна выключыць яго для A/B-параўнання; націскі — тэкставыя падказкі,
  не фанемы BelG2P і не гарантаванае кіраванне вымаўленнем.
- Пакуль да 160 сімвалаў пасля нармалізацыі, адзін сінтэз за раз.
- `mossMaxFrames`: 1–375, 12.5 кадраў/с, не больш за 30 с гуку; пры
  дасягненні ліміту вынік мае папярэджанне аб магчымым абразанні.
- Native 48 kHz stereo зводзіцца ў 48 kHz mono дзеля сумяшчальнасці API.
- Хуткасць 0.5–2 змяняецца праз WSOLA **пасля** генерацыі, без змены тону
  і без `playbackRate`. Гэта не duration-conditioning GlowTTS/OmniVoice.
- Прагрэс, метрыкі, WAV, BUSY, retry і `dispose()` выкарыстоўваюць агульны API.

## Пакоўка (толькі калі эксперымент патрэбны)

```bash
uv run --locked python tools/browser_demo/package_library.py --demo --omnivoice --moss --refresh
uv run --locked python tools/browser_demo/package_library.py --omnivoice --moss --refresh
```

`--moss` уключае ўсе inference-вагі лакальна; без яго дадатковыя рэсурсы не
капіруюцца, а пункт MOSS у запакаваным дэма выключаны. Для MOSS без OmniVoice
можна не перадаваць `--omnivoice`. Гэтыя каманды не разгортваюць сайт.

Пастаўка з усімі рухавікамі перавысіць 1 GiB. Для Netlify лепш CLI, а не
drag-and-drop; абмежаванні хостынгу і трафік трэба праверыць асобна.
