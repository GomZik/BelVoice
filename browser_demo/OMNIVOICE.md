# OmniVoice: асобны эксперыментальны рухавік

Гэта **не замена** лёгкіх GlowTTS-галасоў. Дэма і ESM API выкарыстоўваюць
браўзернае вылічальнае ядро [VocoLoco](https://github.com/Magkino/vocoloco_tts)
з загадзя падрыхтаваным беларускім узорам з BelVoice.

**Вынік эксперыменту:** пакінуць як дэма на Netlify, не інтэграваць у Rudzi.
Тэмбр спадабаўся карыстальніку, але вымаўленне залежыць ад кантэксту,
пераходы паміж гукамі і канцавыя склады недастаткова надзейныя.
Хуткасць 0.85× суб'ектыўна палепшыла вынік; гэта рабочая карыстальніцкая
налада, не праверанае агульнае выпраўленне і не новае значэнне па змаўчанні.

## Мінімальны склад і памяць

- **WebGPU / FP16** — асноўны рэжым дзеля меншай загрузкі: каля 1.3 GB
  (асноўная мадэль, аўдыёдэкодэр і тэкставы tokenizer).
- **WASM / FP32** — яўна выбіраемы CPU-эксперымент, каля 2.5 GB загрузкі.
- **Няма runtime-кланавання:** форма запісу/загрузкі голасу адсутнічае;
  Whisper і аўдыёэнкодэр не загружаюцца наведвальніку. Голас задаецца
  маленькім падрыхтаваным `reference.json`, аднолькавым для абодвух бэкендаў.
- Гэтыя памеры **не роўныя патрэбнай RAM/VRAM**. Ініцыялізацыя і прамежкавыя
  тэнзары патрабуюць дадатковай памяці. FP32/WASM можа выклікаць OOM, закрыць
  укладку або прывесці да завяршэння працэсаў сістэмай. Не запускайце некалькі
  такіх тэстаў/укладак адначасова. Гэта не гарантаваны рэжым для слабых ПК.

WebGPU патрабуе даступны адаптар з `shader-f16`, не толькі наяўнасць
`navigator.gpu`. Калі ён не працуе, рэжым завершыцца памылкай: **няма ціхага
пераходу з 1.3 GB на 2.5 GB**. WASM трэба выбраць і дазволіць асобна.
INT8/INT4 у гэтай інтэграцыі пакуль не рэалізаваныя і не правераныя.

Дадатковыя статычныя worker/runtime/prompt-рэсурсы займаюць каля **26 MiB**,
плюс **12.3 MiB** слоўніка для апцыянальнага ланцужка націскаў, а не
1.3/2.5 GB. Вялікія вагі прыходзяць асобна толькі для выбранага бэкенда.

### Што рэальна праверана

У Chromium на Linux **WASM-сінтэз прайшоў** з фіксаваным беларускім prompt:
«Так.», 8 крокаў, 4 патокі — 1.48 с гуку за 41.36 с сінтэзу (RTF ~28).
Пачатковая загрузка/падрыхтоўка з **лакальнага люстэрка** заняла 10.41 с;
гэта не час спампоўвання з інтэрнэту. Whisper/энкодэр не запытваліся.
Першая спроба пры занятых рэсурсах суправаджалася сістэмным OOM; пасля
вызвалення памяці асобны тэст прайшоў. Такім чынам, WASM магчымы тэхнічна,
але ў гэтым замеры непрыдатны для хуткага агучвання жывых паведамленняў.

У гэтым headless-асяроддзі WebGPU API ёсць, але GPU-адаптар не выдаецца.
Яго хуткасць і фактычны сінтэз **яшчэ не замераныя**. Аўтаматычныя тэсты
правяраюць, што недаступны WebGPU не запускае вялікі WASM-fallback.
Праверкі WAV і інтэграцыі не замяняюць праслухоўванне беларускай якасці.

### Выпраўленне паўтору складоў

Для «Прывітанне! Гэта праверка беларускага сінтэзу маўлення.» пры 16 кроках,
WASM і хуткасці 1.0 лакальны вынік пабітава супаў з WAV карыстальніка з
паўторам. VocoLoco дадаваў да Python-ацэнкі 97 аўдыётокенаў яшчэ 12 запасных
(разам 109). Асобная проба без запасу дала 3.65 с замест 4.05 с;
карыстальнік пацвердзіў адсутнасць заікання ў другім файле.
Падрыхтоўка цяпер адключае гэты запас для абодвух бэкендаў, не змяняючы
ўзору голасу, крокаў, seed або хуткасці. Гэта праверанае выпраўленне гэтага
прыкладу, не гарантыя адсутнасці паўтораў ці абрэзаных слоў на любых тэкстах.

### Вядомы дэфект: страта канцавых складоў

Паводле наступнага праслухоўвання карыстальніка, **цяперашняя канфігурацыя
OmniVoice ўсё яшчэ «пад’ядае» склады на канцы слоў**. Таму адключэнне
12 запасных аўдыётокенаў нельга лічыць поўным выпраўленнем маўленчай якасці:
на правераным сказе паўтор знік, але праблема захавання канчаткаў застаецца.

Недастатковая ацэнка працягласці — магчымая прычына, не пацверджаны дыягназ.
Патрэбны асобны прыклад з дакладным тэкстам, WAV і параметрамі, каб аддзяліць
памылку ацэнкі працягласці ад генерацыі або постапрацоўкі. Аўтаматычна вяртаць
ранейшы запас пакуль не варта: ён узнаўляў паўтор на ўжо правераным прыкладзе.

## Падрыхтоўка

Спачатку сабраць звычайнае дэма паводле [галоўнага README](../README.md#як-атрымаць-такое-ж-дэма-з-зыходнікаў).
Затым, з кораня праекта:

```bash
uv run --locked --extra browser-demo python tools/browser_demo/prepare_omnivoice.py
uv run --locked --extra browser-demo python tools/browser_demo/package_library.py --demo --omnivoice --refresh
uv run --locked --extra browser-demo python browser_demo/serve.py --directory dist/belvoice-demo
```

Скрыпт:

1. Бярэ VocoLoco на зафіксаваным commit
   `7fa8601b9864005e473e14b41756d6e963211d97` і адаптуе worker: лакальны ORT,
   абмежаванне патокаў, адсутнасць encoder-пробы і неяўных fallback,
   вызваленне тэнзараў і асобныя кэшы BelVoice.
2. Пакідае толькі патрэбны ORT WebGPU/WASM runtime 1.30.0, без астатніх
   WASM-варыянтаў. Ён асобны ад runtime існуючых GlowTTS-галасоў.
3. Адзін раз на камп'ютары зборкі выкарыстоўвае ONNX-энкодэр для
   `framework/belvoice/synth/tts/tts-omnivoice/ref.wav` і транскрыпцыі з
   `TTSOmniVoice.py`. Патрэбная разавая загрузка энкодэра каля 654 MB у кэш
   зборкі; у браўзерны пакет ён **не капіюецца**.
4. Запісвае pre-encoded prompt, ліцэнзіі і provenance ў `browser_demo/omni/`.
   Узор мае 13.8 с пасля выраўноўвання; транскрыпцыя захаваная цалкам.
   Выконваюцца mono/resample/RMS/alignment, але не выдаленне цішыні;
   гэта не біт-у-біт паўтор усяго Python-preprocessing.
5. Падрыхтоўвае адназначны слоўнік націскаў з GrammarDB у зафіксаваным
   BelG2P 1.0.0 JAR. Выкарыстоўваецца арыгінальны `GrammarDBStressReader`
   (прыярытэты SPELL → SHOW → ALL), а не выбар першага націску з усіх форм.
   Патрэбны Java, як і для зборкі BelG2P; экспарт і аўдыёэнкодэр працуюць
   паслядоўна. Гатовы слоўнік з праверанымі SHA-256 выкарыстоўваецца паўторна.
   `--grammar-jar /шлях/да/кэшаванага.jar` дазваляе не спампоўваць JAR яшчэ раз.

Вялікія inference-вагі **не ўваходзяць у `dist/`**: пры выбары OmniVoice і
пацверджанні яны загружаюцца з [зафіксаванай HF-рэвізіі](https://huggingface.co/Gigsu/vocoloco-onnx/tree/2c301ff95a826f76ec9ff3d93233318f91362bf5)
і кэшуюцца ў браўзары. Тэкст і аўдыё не адпраўляюцца на сервер сінтэзу.
Па змаўчанні звычайная пакоўка **без `--omnivoice`** выключае гэтыя дадатковыя
runtime-рэсурсы і робіць пункт OmniVoice у запакаваным дэма недаступным.
Гэта дазваляе не павялічваць звычайную пастаўку без патрэбы.

## Паспрабаваць у дэма

1. Выбраць «OmniVoice — беларускі ўзор».
2. Выбраць WebGPU або WASM і пацвердзіць аб'ём загрузкі/ліцэнзію.
3. Для першай пробы ўзяць кароткае `Прывітанне!` і 8 крокаў. 16/32 крокі
   павялічваюць кошт генерацыі; якасць трэба параўноўваць на слых.
4. Сачыць за этапамі і часам. «Спыніць» завяршае Worker, у тым ліку пры
   загрузцы; ужо захаваныя ў кэшы часткі могуць застацца для наступнай спробы.

Абмежаванне — 160 сімвалаў **пасля** нармалізацыі. Пакуль няма разбіцця
доўгіх запытаў. Нармалізацыя лікаў і сімвалаў — наша; далей ідзе тэкставы BPE
OmniVoice, **не фанемы GlowTTS**. BelG2P не ўжываецца.

### Апцыянальныя націскі

`useStressML: true` або сцяжок StressML у дэма ўключае ўвесь **лакальны**
ланцужок: ручныя націскі → StressUsual (адзіная «о/ё») → StressNoHomographs
(адназначны граматычны слоўнік) → StressStat → StressML для рэшты.
Ранейшыя націскі не перапісваюцца пазнейшымі этапамі. Пачатковая вялікая
літара захоўваецца, у тым ліку пры пошуку малой формы ў слоўніку.
Вынік накшталт `Крыптавалю́та` перадаецца ў тэкставы tokenizer OmniVoice;
гэта падказка мадэлі, а не гарантаванае кіраванне вымаўленнем. Для параўнання
можна выключаць опцыю паміж запытамі без перазагрузкі OmniVoice.

Асобны text Worker загружае слоўнік і ляніва загружае WASM-мадэль StressML,
толькі калі патрэбнае прадказанне. Ён не загружае GlowTTS, вакодэр або BelG2P.
Адназначныя словы атрымліваюць **яўныя** тэкставыя націскі са слоўніка,
а не проста прапускаюцца праз ML. Слоўнік змяшчае 1 992 300 форм і займае
каля **12.3 MiB gzip**; загружаецца толькі пры ўключанай опцыі, адзін раз на
рухавік, і патрабуе дадатковай RAM пасля распакавання. Звычайная пакоўка без
`--omnivoice` яго не ўключае. Даныя — GrammarDB са зборкі BelG2P 1.0.0,
не недаступны лакальны каталог распрацоўніка арыгінальнага BelVoice.
SHA-256 даных і зыходнікаў захоўваюцца ў `data/stresses-nohomographs-source.json`.

Кантэкстны StressLLM **не ўключаны**: тут няма LLM/API-запытаў, таму амографы
не разбіраюцца па кантэксце. Час усёй падрыхтоўкі паказваецца ў ML-метрыцы,
а колькасць даданых націскаў па этапах — у `stressML.stageCounts` і дэма.
`dispose()`/«Спыніць» завяршае абодва Worker. Па змаўчанні опцыя выключаная.

## Праграмна (эксперыментальны JS API)

```js
const voice = createBelVoice({
  voice: 'omnivoice',
  backend: 'webgpu', // 'wasm' — асобная яўная проба на CPU
  allowModelDownload: true, // толькі пасля згоды карыстальніка
});
await voice.load();
const audio = await voice.synthesize('Прывітанне!', {
  speed: 1.0,
  omniSteps: 8, // 8, 16 або 32; па змаўчанні 16
  useStressML: true, // правілы + граматычны слоўнік + статыстыка + ML → тэкставыя націскі
});
// 24 kHz mono PCM/WAV; прайграванне, як і раней, робіць прыкладанне.
voice.dispose();
```

`load()` без `allowModelDownload` вяртае `DOWNLOAD_CONSENT_REQUIRED` да
любых сеткавых запытаў. Ёсць звычайныя `BUSY`, `DISPOSED`, памылкі загрузкі
і Worker. Gleam-біндынгі цяпер арыентаваныя на GlowTTS; дазвол на вялікую
загрузку OmniVoice праз іх асобна не выведзены.

## Лакальныя вялікія тэсты (асцярожна)

Толькі на камп'ютары з дастатковай памяццю і **па адным**:

```bash
uv run --locked --extra browser-demo python tools/browser_demo/prepare_omnivoice.py --models wasm
uv run --locked --extra browser-demo python tools/browser_demo/test_omnivoice_browser.py
```

Лакальная копія вагаў ствараецца ў `models/omnivoice-browser/`, не ў `dist/`.
`--models webgpu` спампоўвае меншы FP16-набор; `--models both` — абодва, калі
сапраўды патрэбныя. `modelBaseUrl` у JS API дазваляе падаць уласнае люстэрка.
Для лакальнай дыягностыкі дэма ёсць `?omniModels=/URL/да/люстэрка`.
Сервер люстэрка пажадана павінен падтрымліваць HTTP Range і CORS пры іншым origin.

Невялікія unit-тэсты без вагаў: `node --test tests/browser/test_omnivoice.mjs`.
Праверка сапраўднага StressML і перадачы тэксту (без вялікіх TTS-вагаў;
толькі Worker генерацыі замяняецца заглушкай):

```bash
uv run --locked --extra browser-demo python tools/browser_demo/test_omnivoice_stress_browser.py
```

Для поўнай WASM-генерацыі з націскамі дадайце `--stress-ml` да
`test_omnivoice_browser.py`. Якасць вымаўлення трэба параўнаць на слых.

Асобная падрыхтоўка/праверка слоўніка без вялікіх мадэляў:

```bash
uv run --locked python tools/browser_demo/export_stress_dictionary.py
uv run --locked python tools/browser_demo/test_stress_pipeline.py
```

Бяспечная браўзерная праверка без вялікай загрузкі:

```bash
uv run --locked --extra browser-demo python tools/browser_demo/test_omnivoice_browser.py --probe-only
```
