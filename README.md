# BelVoice - фрэймварк апрацоўкі беларускага маўлення

**Паспрабаваць без усталявання: [belvoice.gomzik.xyz](https://belvoice.gomzik.xyz).**
Два галасы, апцыянальныя ML-націскі і рэгулятар хуткасці; сінтэз выконваецца
на вашым камп’ютары ў браўзары. Першы запуск загружае мадэлі і слоўнікі.

## Пра гэты варыянт

Пашырэнне арыгінальнага [Belarus/BelVoice](https://github.com/Belarus/BelVoice)
для лакальнага сінтэзу і выкарыстання ў браўзары. Захаваныя модулі і аўтарства
арыгінальнага праекта; новыя магчымасці:

- лакальны CLI `speak.py`: беларускі тэкст → WAV на CPU;
- сапраўдны BelG2P у JavaScript праз TeaVM, GlowTTS/HiFi-GAN у ONNX Runtime Web;
- два галасы: **alex73** і **жаночы slapula №1**, з лянівай загрузкай выбранага;
- апцыянальныя ML-націскі для невядомых слоў і праграмная хуткасць `0.5–2.0`;
- дэма з часамі загрузкі/сінтэзу, WAV-экспартам і наладамі Netlify;
- асобная ESM-бібліятэка і callback-біндынгі для Gleam, без аўтапрайгравання.

**У Git захоўваюцца зыходнікі, тэсты і скрыпты зборкі, не гатовыя runtime-assets.**
Пасля clone спачатку выканайце [поўную зборку](browser_demo/README.md#перазборка-з-рэпазіторыя).
Java, Maven і PyTorch патрэбныя пры падрыхтоўцы, але не наведвальніку гатовай
дэма-старонкі: сінтэз цалкам выконваецца ў яго браўзары.

Два пастаянныя выніковыя каталогі (абодва выключаныя з Git):

| Каталог | Прызначэнне |
| --- | --- |
| `dist/belvoice-demo/` | Уся дэма-старонка для Netlify / статычнага хостынгу |
| `dist/belvoice/` | Бібліятэка з абодвума галасамі, StressML і Gleam FFI для іншага праекта |

Інструкцыі: [дэма і зборка](browser_demo/README.md),
[экспарт абодвух галасоў](browser_demo/VOICES.md),
[JavaScript API](browser_demo/LIBRARY.md), [Gleam](integrations/gleam/README.md).
Гэта не сэрвіс кланавання голасу; якасць і інтанацыя абмежаваныя гатовымі
чэкпойнтамі. Ліцэнзіі кода, мадэляў і слоўнікаў трэба разглядаць асобна.

Асобна ёсць [эксперыментальны OmniVoice](browser_demo/OMNIVOICE.md):
беларускі pre-encoded prompt без runtime-кланавання, WebGPU/FP16 з прыярытэтам
меншай загрузкі і цяжкі WASM/FP32-варыянт. Гэта апцыянальная зборка, не
частка звычайных каманд ніжэй. Увага: NC-вагі, высокі расход памяці і
павольны CPU-сінтэз; для камерцыйнага сэрвісу патрэбнае асобнае ўдакладненне правоў.

## Як атрымаць такое ж дэма з зыходнікаў

### Перадумовы

1. Скапіюйце **гэты рэпазіторый/форк** і перайдзіце ў яго корань — каталог
   з `pyproject.toml`. У арыгінальным upstream гэтыя пашырэнні могуць адсутнічаць.
2. Усталюйце [uv](https://docs.astral.sh/uv/getting-started/installation/),
   Python >=3.12 (праверана з 3.13), **JDK 21+** з `java` і `javac`, а таксама
   [Maven](https://maven.apache.org/install.html). Java/Maven патрэбныя для
   зборкі BelG2P; CUDA/GPU не абавязковыя.
3. Патрэбныя інтэрнэт для загрузак і некалькі GB вольнага дыска. Зборка і тэсты
   правераныя на Linux; іншыя сістэмы пакуль не правяраліся.

Праверыць, што інструменты даступныя ў PATH:

```bash
uv --version
java -version
javac -version
mvn -version
```

### Поўная паслядоўнасць каманд

З **кораня рэпазіторыя**, у паказаным парадку:

```bash
# 1. Python-залежнасці, у тым ліку экспарт у ONNX.
uv sync --locked --extra browser-demo

# 2. Два галасы: зыходныя чэкпойнты спампуюцца аўтаматычна ў кэш.
uv run --locked --extra browser-demo python tools/browser_demo/export_models.py --voice default
uv run --locked --extra browser-demo python tools/browser_demo/export_models.py --voice female-1

# 3. Агульная апцыянальная мадэль націскаў.
uv run --locked --extra browser-demo python tools/browser_demo/export_stress_ml.py

# 4. Сапраўдны BelG2P у JavaScript і экспарт GrammarDB.
uv run --locked --extra browser-demo python tools/browser_demo/build_g2p.py

# 5. ONNX Runtime Web/WASM, нармалізацыя і статыстычны слоўнік націскаў.
uv run --locked --extra browser-demo python tools/browser_demo/prepare_assets.py

# 6. Уся дэма-старонка для статычнага хостынгу.
uv run --locked --extra browser-demo python tools/browser_demo/package_library.py --demo --refresh

# 7. Лакальна запусціць менавіта гэтую гатовую зборку з COOP/COEP.
uv run --locked --extra browser-demo python browser_demo/serve.py --directory dist/belvoice-demo
```

Адкрыйце **http://localhost:8000**, выберыце голас, StressML і хуткасць, затым
націсніце **«Агучыць»**. Для жаночага голасу паспрабуйце `1.3–1.4×`.
Каб спыніць сервер, націсніце Ctrl+C. Гэта той жа інтэрфейс і pipeline, што ў
[апублікаваным дэма](https://belvoice.gomzik.xyz); час залежыць ад вашага
камп’ютара, сеткі і кэша. Асабістыя налады выбару голасу/тэксту могуць адрознівацца.

Калі Maven не ў PATH, **замест каманды кроку 4** запусціце яе з
`--maven /поўны/шлях/да/mvn`. Падрабязнасці экспарту кожнага голасу —
у [VOICES.md](browser_demo/VOICES.md).

### Заліць на Netlify або забраць у іншы праект

- **Netlify:** заліце **ўвесь `dist/belvoice-demo/`** праз Deploy manually /
  Netlify Drop. `index.html` і `_headers` павінны заставацца ў корані.
  Build command на Netlify не патрэбны; лакальны сервер публікаваць не трэба.
  Загалоўкі з `_headers` уключаюць шматпаточны WASM.
- **Бібліятэка без інтэрфейсу:** дадаткова выканайце
  `uv run --locked --extra browser-demo python tools/browser_demo/package_library.py --refresh`
  і скапіюйце ўвесь `dist/belvoice/` у іншы праект.

Поўнае дэма з двума галасамі займае каля **376 MiB**. У браўзары загружаецца
толькі выбраны голас; StressML — па патрэбе. Для гатовай старонкі ўжо не
патрабуюцца Java, Maven, Python або ўсталяваныя TTS-праграмы.
Наступныя зборкі абнаўляюць тыя ж папкі праз `--refresh`; уласныя файлы ў іх
не дадавайце. Згенераваныя даныя нармалізацыі, мадэлі і build-вынікі не каміцяцца — толькі
зыходнікі і каманды ўзнаўлення. Аўтаматычныя праверкі прыведзены ў
[README дэма](browser_demo/README.md#перазборка-з-рэпазіторыя).

## Арыгінальны фрэймварк

Гэты фрэймварк дае доступ да перадавых на сённяшні дзень (SOTA) тэхналогій апрацоўкі голасу для беларускай мовы. Наша
галоўная мэта — не проста механічнае пераўтварэнне тэксту ў гук, а забеспячэнне правільнага і натуральнага беларускага
вымаўлення з улікам усіх фанетычных законаў (асіміляцыя, аканне, яканне, змякчэнне і г.д.).

Фрэймварк утрымлівае модулі для сінтэзу (TTS) і распазнавання (ASR) маўлення. Ён пабудаваны па модульным прынцыпе,
прапаноўваючы розныя варыянты рэалізацыі кожнага этапу. Гэтыя варыянты адрозніваюцца па:

* Тыпу кампанентаў (выключна лакальныя або з выкарыстаннем знешніх API).
* Патрабаваннях да вылічальных рэсурсаў (CPU / GPU) і фінансавых выдатках.
* Выніковай якасці апрацоўкі (хуткія чарнавыя варыянты супраць SOTA рашэнняў).

Модулі можна гнутка камбінаваць у залежнасці ад вашых патрэбаў. Яны напісаная на Python, ці маюць Python-абгортку.
Архітэктура дазваляе злучаць модулі простымі выклікамі функцый, а таксама правяраць і падпраўляць прамежкавы вынік на
кожным кроку апрацоўкі.

## Паслядоўнасць сінтэзу маўлення (TTS Pipeline)

Каб атрымаць якасную агучку, тэкст мусіць прайсці некалькі стадый падрыхтоўкі перад самім сінтэзам:

1. **Нармалізацыя** — разгортванне скаротаў, абрэвіятур, ператварэнне лічбаў і сімвалаў у словы ў правільным склоне.
2. **Пазначэнне націскаў** — расстаноўка націскаў ва ўсіх словах тэксту, і вырашэнне спрэчных выпадкаў, калі месца
   націску залежыць ад кантэксту і сэнсу (напрыклад, *му́ка* ці *мука́*). Рэкамендуецца паслядоўная камбінацыя некалькіх метадаў: 
   StressLLM -> StressStat -> StressNoHomographs -> StressML -> StressUsual.
3. **Фанемізацыя (G2P)** — пераўтварэнне літар у гукі (фанемы). Гэта найважнейшы этап для беларускай мовы, бо ён улічвае
   правілы чытання і фанетычныя працэсы (аглушэнне/азванчэнне, мяккасць і інш.).
4. **Сінтэз маўлення** — генерацыя аўдыёфайла па падрыхтаваным тэксце або фанемах.
5. **Канвертацыя і пост-апрацоўка** — сцісканне сінтэзаванага аўдыё ў зручны фармат (opus, mp3 і г.д.) для перадачы
   карыстальніку.

Выклік кожнага модуля не з'яўляецца абавязковым. Напрыклад, пры агучванні абмежаванага набору сказаў (асабліва з
уласнымі імёнамі ці спецыфічнымі тэрмінамі) бывае прасцей зрабіць нармалізацыю і расставіць націскі ўручную.

## Лакальны CLI: беларускі тэкст → WAV

У асяроддзі `uv` і з усталяванай Java/JVM:

```bash
uv sync --locked
uv run speak.py --output test.wav \
  "Прывітанне! Гэта праверка беларускага сінтэзу маўлення."
```

Першы запуск спампоўвае BelG2P 1.0.0 і мадэлі
`alex73/BelarusianTTSviaCoquiTTS`; наступныя выкарыстоўваюць лакальны кэш.
Зафіксаваная рэвізія: `d7684c1dc4bcfd69708bbc013b251549ae40b1ca`.
Сінтэз працуе на CPU праз `coqui-tts` 0.28.0, вынік — WAV, mono, 22050 Hz.
Па змаўчанні файл называецца `output.wav`; каталог выхаднога файла павінен існаваць.
`--help` паказвае аргументы; памылкі вяртаюць ненулявы код завяршэння.

Pipeline: `NormalizationSimple` → `StressStat` → `PhonemizationBelG2P` → `TTSCoquiTTS`.
`StressStat` выкарыстоўвае наяўны `stresses-stat.json` (679 запісаў), выбіраючы
найбольш частотны націск для амографаў і захоўваючы ручныя націскі.
Адсутны `stresses-nohomographs.json` яму не патрэбны: гэты файл прызначаны для
асобнага `StressNoHomographs`. Далей BelG2P выкарыстоўвае
GrammarDB з JAR, убудаваны спіс амографаў і простыя эўрыстыкі для невядомых слоў.
Гэта **не кантэкстнае вырашэнне амографаў**: магчымыя памылкі націску, асабліва
ў імёнах і словах па-за базай. Можна задаваць націск уручную: `му́ка`, `мука́`
(камбінавальны знак U+0301). Адсутны слоўнік адназначных націскаў не аднаўляецца
і не падмяняецца пустым. `StressUsual` не патрабуе слоўніка, але дае толькі
эўрыстыку для «о/ё»; `StressML` патрабуе асобных вагаў і канфігурацыі.
Нармалізацыя застаецца без кантэксту: цэлыя лікі чытаюцца словамі
(`1000` → «адна тысяча», `2026` → «дзве тысячы дваццаць шэсць», `-42` →
«мінус сорак два»). Падтрыманыя разрадныя прабелы (`1 000`, у тым ліку NBSP
і вузкі NBSP) і лікі да 18 лічбаў. Пачатковыя нулі (`00123`) і паслядоўнасці
даўжэйшыя за 18 лічбаў чытаюцца па лічбах. Даты, дробы, валюты і тэлефоны
не распазнаюцца як асобныя фарматы; скланенне паводле суседніх слоў не
ўгадваецца. Лацінка чытаецца назвамі літар. Правілы аднолькавыя ў Python і JS.
Знакі `@`, `%`, `+`, `=`, `€`, `$`, `#`, `&`, `<`, `>` чытаюцца як «слімак», «працэнт»,
«плюс», «роўна», «еўра», «долар», «рашотка», «амперсанд», «менш», «больш» без кантэкстнага скланення.
Непадтрыманыя знакі, напрыклад двукоссі і emoji, становяцца межамі фраз.
Пры вядомай фанетычнай супярэчнасці, напрыклад немагчымай мяккасці `ш`,
BelG2P паўтарае спробу ў набліжаным рэжыме і выдае папярэджанне. Новыя гукі
не дадаюцца, расейская мова не падтрымліваецца асобна, іншыя памылкі не хаваюцца.

### Сумяшчальнасць фанем

У Java API `FanetykaText` 1.0.0 ёсць толькі `ipa`, `skola`, `why`, не `ipa2tts`.
Абгортка выкарыстоўвае рэальныя `Fanetyka3.calcFanetyka(List<String>)` і
`toString(ToStringIPA2TTS())`: націск перад галосным, без зліцця аднолькавых
зычных праз прабел. Словы паміж знакамі прыпынку апрацоўваюцца разам,
каб захаваць міжслоўную асіміляцыю.

Нават гэты Java-серыялізатар мае навейшую натацыю, чым checkpoint GlowTTS.
Таму вынік пераводзіцца ў гістарычную натацыю: `w→v`, `ʋ→β`, `ɦ→ɣ`,
`ɡ→g`, `ʒ→ʐ`, `ʃ→ʂ`, `ɪ→ɨ`. Для новага рэдукаванага `ɐ` выкарыстоўваецца
набліжэнне `a`: асобнага токена ў мадэлі няма. Звычайны IPA замест TTS-вываду
не выкарыстоўваецца. Правяраецца алфавіт канкрэтнага checkpoint-а і яго
tokenizer, каб невядомыя сімвалы не губляліся моўчкі. Канфігурацыі і вагі не мяняюцца.

Крыніцы для праверкі:
[Java API 1.0.0](https://github.com/Belarus/BelG2P/blob/1.0.0/src/main/java/org/alex73/fanetyka/impl/FanetykaText.java),
[TTS-серыялізатар](https://github.com/Belarus/BelG2P/blob/1.0.0/src/main/java/org/alex73/fanetyka/impl/str/ToStringIPA2TTS.java),
[табліца 1.0.0](https://github.com/Belarus/BelG2P/blob/1.0.0/src/main/resources/org/alex73/fanetyka/impl/str/out_ipa_tts.txt),
[гістарычны алфавіт Huk.IPA](https://github.com/Belarus/BelG2P/blob/7bf8e3cdd0a37a6e20f694ad2b14bf12fc2c976a/src/org/alex73/fanetyka/impl/Huk.java),
[рэцэпт навучання Coqui](https://github.com/idiap/coqui-ai-TTS/tree/dev/recipes/bel-alex73).
Алфавіт уваходу таксама зададзены ў `glowtts/config.json` спампаванай мадэлі
(`use_phonemes=false`, `text_cleaner=no_cleaners`).

Для некалькіх сінтэзаў у адным працэсе паўторна выкарыстоўвайце адзін экзэмпляр
`PhonemizationBelG2P` і адзін `TTSCoquiTTS`: база, канфігурацыя і нейрасеткі
захоўваюцца паміж выклікамі. Гэта не гарантыя патокабяспечнасці.

Рэгрэсійныя тэсты (рэальны BelG2P; загрузка нейрасетак замяняецца mock-аб'ектам):

```bash
uv run python -m unittest discover -s tests/synth -p test_local_tts.py
```

## Эксперыментальны сінтэз у браўзары

Самадастатковы прататып знаходзіцца ў [`browser_demo/`](browser_demo/README.md):
беларускі тэкст → BelG2P (JavaScript) → GlowTTS/HiFi-GAN (ONNX/WASM) → аўдыё.
Гатовая папка ствараецца скрыптамі зборкі, мадэлі і WASM у Git не ўключаныя.
У ёй дастаткова статычнага HTTP-сервера; сервер толькі раздае файлы.
Для шматпаточнага WASM у дэма выкарыстоўвайце `python browser_demo/serve.py`
з кораня рэпазіторыя: гэты статычны сервер дадае патрэбныя COOP/COEP-загалоўкі.
Інструкцыя перазборкі вялікіх артефактаў і вынікі рэальных праверак — у яе README.

Для іншага праекта ёсць [браўзерная ESM-бібліятэка](browser_demo/LIBRARY.md)
з `load()`, `synthesize()`, `dispose()` і [Gleam FFI](integrations/gleam/README.md).
У дэма ёсць апцыянальная StressML для націскаў у невядомых словах: пераключальнік
дазваляе параўнаць агучванне з ML і без яго; ручныя і слоўнікавыя націскі захоўваюцца.
`uv run python tools/browser_demo/package_library.py` пакуе ўсе runtime-assets
у `dist/belvoice/` без дэма-інтэрфейсу. Для паўторнай зборкі дадайце `--refresh`.
`uv run python tools/browser_demo/package_library.py --demo --refresh` абнаўляе
`dist/belvoice-demo/`. Пакоўшчык правярае manifest і не выдаляе дадатковыя ці
змененыя карыстальнікам файлы.

### Галасавы API

Пасля капіявання **ўсяго** `dist/belvoice/` у `public/belvoice/`:

```js
import {createBelVoice} from '/belvoice/belvoice.js';

const voice = createBelVoice({voice: 'female-1', numThreads: 0});
const audio = await voice.synthesize('Прывітанне, стрымерскі рудзі!', {
  useStressML: true,
  speed: 1.35,
});
// audio.samples, audio.sampleRate, audio.wav — без аўтаматычнага прайгравання.
// Паўторна выкарыстоўвайце voice; dispose() — калі рухавік больш не патрэбны.
```

Для шматпаточнага WASM патрэбныя COOP/COEP на вашым хостынгу. Без іх працуе
бяспечны аднапатачны рэжым. Не перанакіроўвайце запыты да assets на HTML SPA.

## Паслядоўнасць распазнавання маўлення (ASR Pipeline)

Звычайна працэс абмяжоўваецца выклікам аднаго ASR-модуля, але для атрымання ідэальнага тэксту пайплайн можа быць
пашыраны:

1. **Разбіўка на часткі** — вылучэнне маўлення з аўдыё і падзел яго на асобныя фрагменты (з пазнакамі часу і асобных
   спікераў).
2. **Аналіз спікераў** — вызначэнне асоб спікераў у аўдыё (пол, узрост, пошук вядомых спікераў).
3. **Аб'яднанне частак** — дазваляе рабіць распазнаванне праз мадэлі (Gemini), якія псуюць timestamp на вялікіх файлах,
   і значна памяншае колькасць запытаў.
4. **Распазнаванне маўлення (Speech-to-Text)** — пераўтварэнне аўдыё ў сыры тэкст.
5. **Зваротная нармалізацыя (ITN)** — канвертаванне слоў-лічбаў назад у лічбавы фармат, разбіўка тэксту на сказы і
   абзацы, расстаноўка знакаў прыпынку.
6. **Выпраўленне правапісу** — прывядзенне тэксту да актуальнага правапісу (2008).

## Фарматы аўдыё

Аптымальныя параметры аўдыяфайлаў для распазнавання: wav фармат без кампрэсіі, 16000 Hz, 16-bit, mono. Хоць некаторыя
модулі падтрымліваюць іншыя фарматы, яны могуць працаваць з імі некарэктна.

## Рэсурсы для апрацоўкі

Паколькі большасць модуляў абапіраецца на нейрасеткі, важна ўлічваць патрабаванні да «жалеза». Выкарыстанне знешніх
правайдэраў (хмарных API) уплывае на прыватнасць звестак, патрабуе стабільнага інтэрнэту і стабільнай працы знешніх
правайдэраў.
Для кожнага модуля ў спісе ніжэй пазначана, як ён працуе (лакальна/знешне) і якія вылічальныя магутнасці яму патрэбныя.

Некаторыя модулі выкарыстоўваюць `TORCH_DEVICE` для пераносу апрацоўкі на CUDA альбо MPS.

# Спіс модуляў

### Нармалізацыя - `belvoice.synth.normalization.NormalizationSimple`

* **Апісанне:** Вербалізуе цэлыя лікі без кантэкстнага скланення, а лацінскія літары — іх назвамі з
  англійскага алфавіта. Таксама агучвае `@ % + = € $ # & < >` фіксаванымі беларускімі назвамі.
  Варта выкарыстоўваць выключна для хуткіх тэстаў.
* **Рэсурсы:** Працуе вельмі хутка на CPU.
* **Залежнасці:** няма.

### Нармалізацыя - `belvoice.synth.normalization.NormalizationLLM`

* **Апісанне:** Разумная нармалізацыя праз вялікія моўныя мадэлі (LLM). Якасць узгаднення склонаў і разгортвання
  складаных абрэвіятур наўпрост залежыць ад абранай LLM. Падтрымлівае карыстальніцкія промпты для ўліку спецыфікі вашага
  тэксту (напрыклад, гласарыя тэрмінаў).
* **Рэсурсы:** Патрабуе доступу да знешняга правайдэра (для мадэляў кшталту Gemini ці GPT) альбо ўласнай магутнай
  відэакарты (GPU) для лакальнага запуску мадэляў накшталт Llama ці Gemma.
* **Параметры:** `model_name` - з старонкі https://models.litellm.ai/.
  API ключ дадаецца ў залежнасці ад мадэлі. Напрыклад, для Gemini трэба пазначыць `GEMINI_API_KEY` у пераменных
  асяроддзя.
  Падрабязнасці - на https://docs.litellm.ai/docs/providers/gemini
* **Залежнасці:** `conda create --name asr python=3.12; conda activate asr; pip install litellm==1.83.13`

### Пазначэнне націскаў - `belvoice.synth.stress.StressStat`

* **Апісанне:** Пазначае націскі на падставе Граматычнай базы беларускай мовы і вырашае праблему амографаў статыстычным
  метадам — абапіраючыся на слоўнік найбольш частотных варыянтаў націску. Нягледзячы на прастату падыходу, тэсты
  паказваюць правільнасць у больш чым 80% выпадкаў.
* **Рэсурсы:** Працуе на CPU вельмі хутка.
* **Залежнасці:** няма.

### Пазначэнне націскаў - `belvoice.synth.stress.StressML`

* **Апісанне:** Пазначае націск нейрасеткай (char-Transformer з pointer-softmax па галосных), навучанай на
  Граматычнай базе беларускай мовы. Прызначана перадусім для слоў, якіх няма ў слоўніку (гл. `StressNoHomographs`/
  `StressStat`) - выкарыстоўваецца як «запасны варыянт» для OOV-слоў.
* **Рэсурсы:** Працуе на CPU вельмі хутка (невялікая мадэль).
* **Заўвагі:** Падрабязнасці пра ідэю, дадзеныя і навучанне - гл. `tools/stress_ml/README.md`.
* **Залежнасці:** `torch`, `safetensors`.

### Пазначэнне націскаў - `belvoice.synth.stress.StressLLM`

* **Апісанне:** Пазначае націскі на падставе Граматычнай базы беларускай мовы. Для амографаў выклікаецца LLM для аналізу
  граматычных характарыстык слова(на падставе Граматычнай базы) і ягонага значэння (на падставе Тлумачальнага слоўніка)
  у канкрэтным сказе і па гэтым абіраецца варыянт націску. Такі падыход дае найлепшую якасць.
* **Рэсурсы:** Знешні правайдэр (Gemini/GPT) або GPU (Gemma/Llama).
* **Залежнасці:** `pip install litellm==1.92.0`

### Фанемізацыя - `belvoice.synth.phonemization.PhonemizationBelG2P`

* **Апісанне:** Пераводзіць тэкст у транскрыпцыю (фанемы) праз BelG2P. Калі TTS-модуль падтрымлівае фанемны ўвод,
  выкарыстанне BelG2P **крытычна паляпшае натуральнасць вымаўлення**. Модуль улічвае складаныя выпадкі беларускай
  фанетыкі: асіміляцыю зычных па глухасці/звонкасці і мяккасці, прыстаўныя гукі, правільнае вымаўленне злучнікаў і
  прыназоўнікаў у патоку маўлення.
* **Рэсурсы:** Працуе CPU дастаткова хутка.
* **Заўвагі:** Спампоўвае 22MiB jar з github.com і патрабуе ўсталяванай java для працы. Можна задаць зменную асяроддзя 
  `PHONEMIZATION_BELG2P_JAR` каб jar не спампоўваўся, а браўся з гэтага шляху.
* **Залежнасці:** `conda create --name asr python=3.12 conda-forge::jpype1=1.7.0 pooch=1.9.0`

### Сінтэз маўлення - `belvoice.synth.tts.TTSCoquiTTS`

* **Апісанне:** Выкарыстоўвае мадэль CoquiTTS, натрэніраваную на беларускім голасе з Mozilla CommonVoce. Працуе з
  фанемамі ад `PhonemizationBelG2P` у гістарычнай натацыі checkpoint-а. Запускаецца лакальна праз `coqui-tts`.
* **Рэсурсы:** Вельмі хутка генеруе аўдыё на GPU, але цалкам прыдатна для працы і на звычайным CPU.
* **Залежнасці:** існуючае асяроддзе `uv` з залежнасцямі з `pyproject.toml`; гл. лакальны CLI вышэй.

### Сінтэз маўлення - `belvoice.synth.tts.TTSOmniVoice`

* **Апісанне:** SOTA-мадэль для максімальна натуральнага сінтэзу.
* **Рэсурсы:** Патрабуе GPU.
* **Залежнасці:** `conda create --name asr python=3.12; conda activate asr; pip install omnivoice==0.2.1`

### Распазнаванне маўлення - `belvoice.asr.stt.STTNvidia`

* **Апісанне:** Выкарыстоўвае мадэлі Nvidia NeMo. Найлепшая мадэль: `nvidia/stt_be_fastconformer_hybrid_large_pc`, але і
  яна мае праблемы з разбіўкай на сказы.
* **Рэсурсы:** Працуе на CPU даволі хутка, можа выкарыстоўваць GPU. На i5-11600 10-хвіліннае аўдыё канвертуецца за ~65
  секунд.
* **Залежнасці:** `conda create --name asr python=3.12; conda activate asr; pip install nemo_toolkit[asr]==2.7.3`

### Распазнаванне маўлення - `belvoice.asr.stt.STTFacebook`

* **Апісанне:** Выкарыстоўвае мадэлі Omnilingual ASR. Найлепшыя: `omniASR_LLM_Unlimited_*_v2`. Яны не дадаюць пунктуацыю
  наогул, але дакладна паказваюць гукі. Можна выкарыстоўваць для алічбоўкі дыялектнага маўлення.
* **Рэсурсы:** Працуе на GPU. omniASR_LLM_Unlimited_1B_v2 на Nvidia 5060Ti/16GiB апрацоўвае 5-хвіліннае аўдыё за 42
  секунды.
* **Залежнасці:**
  `conda create --name asr python=3.12 pytorch==2.8.0 torchaudio==2.8.0 conda-forge::libsndfile==1.0.31; conda activate asr; pip install git+https://github.com/facebookresearch/omnilingual-asr.git@81f51e224ce9e74b02cc2a3eaf21b2d91d743455 fairseq2==0.6.0 --extra-index-url https://fair.pkg.atmeta.com/fairseq2/whl/pt2.8.0/cpu`.
  Змяніце /cpu на нешта больш прыдатнае - дэталі на https://github.com/facebookresearch/fairseq2#variants.

### Распазнаванне маўлення - `belvoice.asr.stt.STTGemini`

* **Апісанне:** Выкарыстоўвае мадэлі Gemini. На сённяшні дзень (ліпень 2026 года) мадэлі Gemini, забяспечваюць, бадай, 
  самае дакладнае распазнаванне маўлення з разуменнем кантэксту і добрай пунктуацыяй.
  Але якасць вельмі залежыць ад мадэлі і промпту - мадэлі 3.5 і вышэй не глядзяць на temperature і часта робяць памылкі ў распазнаванні.
  Пакуль раім выкарыстоўваць gemini-3.1-flash-lite.
  Падтрымлівае файлы: wav, mp3, aiff, aac, ogg, opus, flac.
* **Рэсурсы:** Патрабуецца знешні правайдэр.
* **Залежнасці:** `pip install google-genai==2.20.0`, патрэбны `GEMINI_API_KEY` у пераменных асяроддзя.

### Распазнаванне маўлення - `belvoice.asr.stt.STTGeminiLive`

* **Апісанне:** Выкарыстоўвае мадэлі Gemini Live Translate. 
  Gemini Live Translate падаюць вельмі добры транскрыпт, але толькі з хуткасцю самога гучання аўдыё, блокамі не больш за 10 хвілін, і тэкстам без разбіўкі на абзацы.
  З іншага боку, лімітаў на бясплатнае выкарыстанне няма.
  Атрыманы тэкст можна перафарматоўваць праз нейкую простую мадэль.
  Падтрымлівае файлы: wav, mp3, aiff, aac, ogg, opus, flac.
* **Рэсурсы:** Патрабуецца знешні правайдэр.
* **Залежнасці:** `pip install google-genai==2.20.0`, патрэбны `GEMINI_API_KEY` у пераменных асяроддзя.

### Распазнаванне маўлення - `belvoice.asr.stt.STTWhisper`

* **Апісанне:** Выкарыстоўвае мадэлі OpenAI Whisper. 
  З мадэляў Whisper добрая якасць распазнавання атрымліваецца толькі ў `whisper-large-v3`.
  Падтрымлівае файлы: wav, mp3, aiff, aac, ogg, opus, flac.
* **Рэсурсы:** Рэкамендуецца GPU.
* **Залежнасці:** `pip install faster_whisper==1.2.1 torch==2.13.0`.

### Разбіўка на часткі - `belvoice.asr.split.SplitPyannote`

* **Апісанне:** Выкарыстоўвае мадэлі pyannote/speaker-diarization-community-1 ці pyannote/segmentation-3.0 для
  выдзялення маўлення з аўдыё і падзелу яго на асобныя фрагменты з пазнакамі часу. Можа вызначаць спікераў, альбо проста
  разбіваць на часткі.
* **Рэсурсы:** Працуе на CPU, але для вялікіх аўдыёфайлаў рэкамендуецца GPU.
* **Залежнасці:** `conda create --name asr python=3.12; conda activate asr; pip install pyannote.audio==4.0.4`

### Разбіўка на часткі - `belvoice.asr.split.SplitSilero`

* **Апісанне:** Выкарыстоўвае мадэль Silero VAD для выдзялення маўлення з аўдыё.
* **Рэсурсы:** Працуе на CPU, але для вялікіх аўдыёфайлаў рэкамендуецца GPU.
* **Залежнасці:** `conda create --name asr python=3.12 numpy=2.4.4; conda activate asr; pip install silero-vad==6.2.1`

### Аб'яднанне частак - `belvoice.asr.merge.MergeWindow`

* **Апісанне:** Аб'ядноўвае малыя фрагменты аўдыё ў адзін фрагмент - шукае фрагменты, якія агулам даюць працягласць не
  больш за патрэбную.
* **Рэсурсы:** Працуе на CPU вельмі хутка.
* **Залежнасці:** няма.

### Аб'яднанне частак - `belvoice.asr.merge.MergeGraph`

* **Апісанне:** Аб'ядноўвае малыя фрагменты аўдыё ў адзін фрагмент - шукае фрагменты як абыход графа.
* **Рэсурсы:** Працуе на CPU вельмі хутка.
* **Залежнасці:** `pip install networkx==3.6.1`

### Зваротная нармалізацыя (разбіўка на абзацы) - `belvoice.asr.itn.ITNParagraphs`

* **Апісанне:** Разбівае тэкст на лагічныя абзацы праз LLM (выкарыстоўваючы LiteLLM). Тэкст разбіваецца на сказы, нумаруецца тэгамі `{{{id}}}` і апрацоўваецца батчамі з вяртаннем JSON-спісу ідэнтыфікатараў пачатку абзацаў.
* **Рэсурсы:** Патрабуецца знешні правайдэр праз LiteLLM (напрыклад, Gemini ці іншыя).
* **Залежнасці:** `pip install litellm`
